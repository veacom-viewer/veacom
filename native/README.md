# VEAcom native imaging core

The installer includes the codec notices in `THIRD_PARTY_NOTICES.txt` and Rust dependency notices in `RUST_LICENSES.txt`. When desktop dependencies change in the workspace `Cargo.lock`, regenerate the Rust notices from the repository root with cargo-about 0.9.3:

```sh
cargo about generate --locked --manifest-path native/Cargo.toml --config native/about.toml native/licenses.hbs --output-file native/RUST_LICENSES.txt
```

Build with `cargo build --release` and test with `cargo test` in this directory. CMake and a C++ compiler (Clang or MSVC) are required to build the bundled static CharLS JPEG-LS codec; no separate CharLS library is needed at runtime. The executable is `target/release/veacom-core` (`.exe` on Windows).

JPEG 2000 uses the vendored OpenJPEG 2.5.3 C codec through `openjpeg-sys`; the existing C compiler builds and statically links it on macOS and Windows. There is no extra OpenJPEG runtime DLL. The former `openjp2` Rust port invoked an invalid null deallocation on a valid synthetic image. Do not enable both backends. The C backend has been built and checked on macOS; the post-audit Windows build is still pending.

`tests/check_color.py <executable> --output-dir <directory>` generates synthetic color ultrasound fixtures and compares individual frames, complete volumes and decompressed exports with independent pydicom/Pillow decoding. Install its test dependencies with `python -m pip install pydicom numpy Pillow pyjpegls pylibjpeg pylibjpeg-openjpeg`. It covers native/RLE RGB and YBR_FULL, JPEG, JPEG-LS component/line/sample interleaving (including mixed-interleave multiframe files), and JPEG 2000 RGB, YBR_FULL and YBR_RCT. Color conversion uses the stored component space: JPEG and JPEG 2000 RCT/ICT decoders return RGB, whereas RLE, JPEG-LS and JPEG 2000 YBR_FULL retain YBR values. Decompressed exports preserve those values with the correct photometric tag and normalized JPEG-LS component layout.

Before decoding, JPEG/JPEG-LS/JPEG2000 headers are checked against the DICOM dimensions, component count and precision. JPEG2000 checks also cover image/tile geometry, signedness and color transforms. Header inspection crosses fragments without concatenating image payloads and reads at most 1 MiB of headers per frame. RLE headers, segment offsets and exact packet expansion are checked without allocating decoded output. These checks address the tested malformed inputs; they are not a claim that every possible codec defect is contained. Subsampled JPEG2000, custom Part 2 color transforms, native packed YBR_FULL_422, and ambiguous multi-frame fragment layouts without a basic offset table are explicitly unsupported.

After generating the color fixtures, run `tests/check_codec_guard.py <executable> <directory>/fixtures --report <report.json>`. It verifies frame loading, volume loading and decompressed export reject contradictory JPEG/JPEG-LS/JPEG2000 headers and malformed RLE packets, while an already loaded valid study remains available. Rust tests separately reject tiny headers declaring enormous images before calling any decoder.

Electron starts the engine with private stdin and stdout pipes. Protocol 2 uses a 9-byte little-endian header (kind, request ID and payload length). A request carries its JSON call and optional binary data. The engine sends a response head with status, headers and length. Small JSON replies of up to 16 KiB follow immediately. Every pixel chunk and every larger reply needs credit from the consumer. Main grants one chunk of up to 1 MiB per pending read, with an 8 MiB connection limit and 1 MiB reserved for control calls. Up to four volumes and four frames can be open at once. The remaining requests wait in bounded queues.

Dedicated workers handle catalog changes, volume reads, frames, control calls, two concurrent tool operations, picture polls and picture answers. Pending requests can be cancelled before taking a worker. Once running, an operation owns its turn through completion or rollback. Shutdown and stdin EOF stop admission and drain the workers before releasing the catalog and extracted archives. The protocol writer owns a private copy of stdout on Unix and Windows. See `src/pipe.rs` and `electron/engine-pipe.cjs`.

## API

| Operation (`op`, `body`) | Result |
| --- | --- |
| `health` | Version, protocol and codec/import capabilities |
| `import`, `{paths: string[], requestId?}` | `{series, warnings}`; local files, folders, and ZIP archives |
| `importEarly`, `{after, requestId}` | The series the running import has published so far, from the `after`th |
| `series` | `{series, warnings}` for imported series |
| `removeSeries`, `{ids}` | `{removed, remaining}`; forgets the series and their decoded volumes |
| `frame`, `{id, index}` | One frame, with an independent decode permit |
| `volume`, `{id}` | Ordered complete volume |
| `warm`, `{id}` | 202; decodes the volume in the background for the `volume` request that follows |
| `tags`, `{id, frame?}` | Array of `{tag,name,vr,value}` entries |
| `progress` | `{id,running,stage,completed,total,cancelled}` |
| `cancel`, `{id}` or no body | `{requested}`; cancel the job `id` names (from `progress`), or without a body whatever runs |
| `shutdown` | `{ok:true}`; cancel pending work and exports, remove extracted archives and exit cleanly |
| `measure`, `{seriesId,points,kind,plane?}` | Physical measurement or scalar statistics |
| `export`, `{seriesIds,directory,anonymize,dicomdir,decompress,operation?}` | New export directory, copied file count, warnings |
| `exportEstimate`, as `export` | Estimated ZIP size and time |
| `register`, `{fixedId,movingId,fixedRevision,movingRevision}` | `{matrix,rotation,shift,centre,angle,similarity,similarityBefore,overlap,evaluations,levels}`; the rigid transform laying the moving series over the fixed one (below) |
| `exportCancel`, `{operation}` | `{requested}`; stop that export at its next file |
| `processCounters` | This process's CPU time and resident memory |
| `pictureNext` | Waits up to 20 seconds for a picture. The reply carries its ID and operation in `X-Picture-Id` and `X-Picture-Want`. A probe contains the first 64 KiB. Size and pixel requests carry the full file. An idle poll returns 204. |
| `pictureAnswer`, `{id, width, height, offset, more}` or `{id, error}` | Main sends dimensions and, for pixels, RGBA in chunks of up to 1 MiB. Each successful chunk returns 204. An incomplete probe requests the full file. |

Errors are `{error}` with the English message, plus `note` when the message is coded. Every `warnings`
array (import, series, export) has a `warningNotes` array of the same messages. A note is
`{code, params?, text}`: `text` is the English, `code` is stable, and a parameter is text or another
note (the reason a file could not be read). The interface translates notes by code
(`electron/core-messages.json`, `src/i18n/core.ts`) and shows `text` for anything it does not know.
New user-facing messages use `note!` or `coded!` (`src/message.rs`); internal invariant errors stay
plain text.

Image bodies contain little-endian scalar or interleaved RGB samples. **Always read `X-Pixel-Type` and `X-Components`**, including for first-frame responses. Pixel type is `int16`, `uint16`, `uint8`, `float32`, or `float64`. Metadata contains a conservative hint; actual decoded values can use a more compact exact type. Full-range 32-bit integers and double-float pixels use Float64 when Float32 would lose precision or range. Float64 source arrays stay intact for measurements while the frontend makes a separate GPU display copy. Scalar values include the per-frame modality rescale exactly once. They do not include window/level or MONOCHROME1 display inversion. PET `suvFactor`, when available, converts these modality values to SUVbw.

Volumes use z/y/x storage order with x contiguous. Geometry uses patient LPS coordinates; the row-major direction matrix has image i, j, k directions as columns. Physical coordinates equal `origin + direction * (index * spacing)`. Gantry tilt retains the actual slice displacement, so directions need not form an orthogonal matrix. Missing, duplicate or irregular planes disable reconstruction. `spacingKnown` and `orientationKnown` prevent presentation defaults being mistaken for source calibration or laterality. Consistently calibrated ultrasound tissue regions supply in-plane spacing when PixelSpacing is absent; centimetres convert to millimetres, while incompatible regions or nonspatial units do not create a calibration.

Measurement points are patient LPS millimetres. Length/polyline returns `{kind,value,unit:'mm'}`; angle/cobb uses degrees; probe returns voxel index, world position and modality value. Rectangle/ellipse/polygon returns area, sample count, mean, minimum, maximum and population standard deviation, with SUV statistics when calibrated. Native-plane regions sample source voxel centres. Optional `plane: {origin:[x,y,z],u:[x,y,z],v:[x,y,z]}` selects an oblique sampling plane: `u` and `v` are perpendicular patient-space axes. Oblique statistics use trilinear samples and return `sampling:'plane-grid-trilinear'` with `sampleSpacing:[u_mm,v_mm]`. Invalid physical geometry produces an explicit error; irregular stacks currently cannot use this shared-volume measurement API even for an individual calibrated frame.

## Registration

`register` finds the rotation and translation (six degrees of freedom) that lay one volume over another acquired apart: two visits of one patient, or a PET over a CT or MR from another session (`src/registration.rs`). It maximises normalised mutual information (Studholme 1999) between box-averaged copies of the two volumes, at about 8 mm, then 4 mm, then the finest each allows within 8 million voxels. The coarsest level first tries shifts along the patient's long axis, the table axis, and the three best start the search of all six parameters; every level refines them by compass search. The fixed volume is read at about 130,000 points on a regular grid, each set off within its voxel by a repeatable jitter; a transform counts only while half the points the moving volume could hold fall inside it. The result is deterministic: no random numbers, a fixed order of work, and each candidate transform measured by one thread.

`matrix` is row-major 4 × 4 and takes a point of the moving series' patient coordinates (LPS mm) to the fixed series'. `rotation` (degrees about x, y, z, in that order) and `shift` (mm) give the other way, fixed to moving: p ↦ R (p − `centre`) + `centre` + `shift`. `similarity` is the entropy correlation coefficient at the result, from 0 for unrelated images to 1 for images that determine each other; `similarityBefore` is the same with the two series' coordinates taken as one. `overlap` is the share of the fixed points inside the moving volume. Pixels are never resampled or changed: the interface applies the transform when it draws and samples. A series that is not a placed volume is refused (`registration.needsVolumes`), as is a pair that shares too little (`registration.failed`); a series replaced since the request answers 409.

## Limits and verification

The LRU decoded-volume cache defaults to 256 MiB; `VEACOM_CACHE_MIB` can set 64–2048 MiB. Large volumes are released after transfer rather than held beside the frontend's original data and GPU texture. On macOS and Linux, allocations of 32 MiB or more are mapped directly from the operating system (`src/memory.rs`), so releasing a large volume returns its memory at once. macOS otherwise hands a freed block that large back only later: the engine kept a served 1,000-slice CT (500 MiB) resident for anything from under a second to 20–40 s. Smaller volumes still use the system allocator, which may keep their memory after eviction. Windows is unchanged: its heap already returns blocks this large on free (measured on the Tesla T4 VM). A decoded output is limited to 2 GiB, with at most eight decode workers. Import limits are 50,000 entries, 2 GiB per archive file and 8 GiB expanded archive data. Cancellation is checked at file/frame boundaries; a cancelled decode is never published as a complete volume.

DICOM structure is checked iteratively before the object parser runs, including sequences after pixel data. Validation and parsing use the same open file handle. Limits are 32 sequence levels, 32 MiB metadata per file, 1 MiB per metadata value, 64 KiB file meta, and 200,000 elements/items. Pixel lengths and frame counts must agree; compressed frame offsets must point to valid fragment boundaries. Imports additionally cap the sum at 50,000 frames, 64 MiB parsed headers and 256 MiB estimated retained frame metadata, checked before bulk frame copies. The session catalog is capped at 100,000 frames and 512 MiB estimated catalog storage. These catalog limits are not whole-process RSS limits; decoded buffers and the renderer use separate memory. Invalid imports return an error without replacing previously loaded studies.

ZIP extraction directories carry an ownership marker and a cross-process lock. Normal shutdown removes them. After a crash or force-quit, the next startup removes only marked, unlocked directories owned by the current account. Windows creation explicitly assigns the current user SID before writing extracted patient files, including elevated launches. Other active engines, unmarked legacy directories, malformed markers and symlinks are left alone. Failed deletion is reported as a count without patient paths. Old unmarked leftovers require separate manual review; a crash can leave newly extracted files until the viewer starts again.

Native codecs cover uncompressed 8/16/32-bit scalar pixels, FloatPixelData/DoubleFloatPixelData, RLE, JPEG, JPEG-LS and JPEG 2000. Native wide scalars support both byte orders; legacy scalar RLE32 is also decoded with strict bounds. Floating NaN/Infinity padding remains in the source buffer; measurements containing nonfinite samples fail explicitly. PNG, JPEG and BMP pictures, RGB DICOM and direct/segmented palette-color DICOM are supported for 2D display. The engine decodes no picture itself: it tells PNG, JPEG and BMP apart by their first bytes and has Chromium decode them in the desktop app's sandboxed picture decoder (`src/pictures.rs`, `electron/picture-decoder.cjs`); other picture formats are refused before any decoder runs. Concurrent picture reads share 16 MiB of encoded input. A file above this size runs alone, up to 256 MiB. A picture's size is asked for only when nothing in the import is DICOM, since pictures beside DICOM are not series. Ordinary pictures have 8-bit RGB display output. Chromium's conversion from an opaque 16-bit PNG can differ by one level from the previous decoder. For example, the stored channel value `0x00ff` displays as 0. Transparent pixels can also lose their stored RGB on the canvas. JPEGs keep their encoded dimensions and follow EXIF orientation. DICOM 16-bit palette tables use their high eight bits for display while original DICOM exports retain the complete table. Nonopaque alpha palettes require an RGBA viewport and fail explicitly. Nonlinear modality LUTs remain unsupported; the previous app also only applied slope/intercept. RAR archives are refused with a message asking the user to extract them first. Archive contents remain in private temporary directories until the process exits. Ship `THIRD_PARTY_NOTICES.txt` with the app, including the CharLS and OpenJPEG notices.

Export accepts `seriesIds: string[]` and deduplicates source files across selected series; legacy `seriesId: string` remains accepted. `anonymize`, `dicomdir` and `decompress` default to false. Source bytes are preserved unless metadata cleanup or decompression is requested. `decompress:true` writes supported compressed images as Explicit VR Little Endian while preserving stored values, geometry, rescale and original UIDs (unless cleanup remaps them). DICOMDIR creation and reopening are verified independently with pydicom FileSet. ISO creation belongs to the desktop media exporter; this API creates the source directory.

The legacy API flag `anonymize:true` performs **partial metadata cleanup, not anonymization**. The UI calls it “Remove selected identifiers”. It removes private tags, person names, selected patient/institution identifiers, identifying comments, institution code sequences, previous identity containers and invalidated signatures. This applies recursively inside sequences. Selected instance, study, series and frame-of-reference UIDs are remapped consistently across one export. Patient pseudonyms are random per export. `PatientIdentityRemoved` is explicitly **NO**, including when the input claimed YES; inherited de-identification profile codes are removed. `DeidentificationMethod` describes the partial cleanup without claiming a DICOM confidentiality profile.

Acquisition dates/times, age, sex, weight, height, other clinical text and pixels remain and can identify a patient. The output requires review before sharing. Exact acquisition/injection timing, standard PET calibration, modality rescale and geometry are retained; changing dates independently would damage PET uptake calculations. Cleanup is blocked when PET quantitation depends on a private SUV calibration tag, because removing that tag could change SUV values. The error asks the user to export without cleanup or use a validated de-identification workflow. Burned-in annotations are not removed, and a source declaration of burned-in text produces a warning. This does not implement the full [DICOM confidentiality profile](https://dicom.nema.org/medical/dicom/current/output/chtml/part15/chapter_E.html); the distinction is required by the meaning of [Patient Identity Removed](https://dicom.nema.org/medical/dicom/current/output/chtml/part03/sect_C.7.html). The standard also describes why [temporal changes must preserve PET timing](https://dicom.nema.org/medical/dicom/current/output/chtml/part15/sect_E.3.6.html).

Rust tests cover geometry, rescale and stored-bit correctness, multiframe transforms, RGB, archive safety, tags and export. `node tools/check-engine-import.cjs <study-folder>...` imports folders through the engine's pipes, as the app does, and decodes every series. `tests/check_export_cleanup.py <executable> --report <output.json>` requires pydicom and checks the legacy cleanup field list, nested identifiers, inherited confidentiality claims, DICOMDIR reopening, unchanged standard PET SUV after reimport, and rejection of cleanup that would lose private PET calibration.
